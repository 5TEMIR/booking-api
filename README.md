# Booking API — MISE тестовое задание (Backend Trainee)

REST API для онлайн-бронирования столика в ресторане.

**Стек:** Python 3.13+, FastAPI, Pydantic v2, SQLAlchemy 2.0 (async), SQLite (aiosqlite), Alembic, Uvicorn.

## Запуск через Docker

```bash
docker compose up --build
```

## Тесты

Установка зависимостей:

```bash
poetry install
```

Запуск:

```bash
poetry run pytest
```

## Принятые решения

- **Входные валидаторы отделены от схем ответа.** Общие поля вынесены в `BookingBase`,
  а правила бизнес-валидации (имя, телефон, диапазоны даты/времени) живут только в
  `BookingCreateSchema`. `BookingSchema` (ответ) не наследует `field_validator`-ы — иначе
  чтение брони с уже прошедшей датой снова прогоняло бы проверку «не раньше сегодня» и
  роняло `GET /bookings` в 500 на следующий день после брони. Валидация на входе (POST)
  при этом не меняется и по-прежнему возвращает 422.
- **Бизнес-логика.** Правила (даты ±90 дней, слоты 12:00–22:00, телефон, имя) —
  чистые функции в `services/`, не зависят от БД и переиспользуются
  валидаторами Pydantic.

## Что осталось бы доделать

- Пагинация списка броней.
- Защита от гонки при одновременном бронировании одного слота (уникальный индекс на пару
  `booking_date + booking_time` для активных броней).
